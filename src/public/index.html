Q4: Troubleshooting the JavaScript Reducer

Root cause analysis, working solution, and defensive coding best practices

❌ The Buggy Code
function getTotalUsageMB(records) {
  return records.reduce((total, record) => {
    total += record.dataUsageMB;
  });
}

Why It Breaks:

  • No return in arrow body: The arrow callback uses curly braces { ... } without an explicit return statement. It returns undefined on iteration 2, making total = NaN.
  • Missing initial value 0: Without an initial accumulator, reduce() starts with the first object { subscriberId: 'SUB01', ... } as total, resulting in string coercion "[object Object]1200", and crashes with TypeError if given an empty array []!
✅ The Fixed Solution
function getTotalUsageMB(records) {
  if (!Array.isArray(records)) return 0;
  return records.reduce((total, record) => {
    return total + ((record && record.dataUsageMB) || 0);
  }, 0);
}

// Or clean 1-liner:
const getTotalUsageMB = (records = []) =>
  records.reduce((acc, r) => acc + (r?.dataUsageMB || 0), 0);

How to Prevent in the Future:

  • ESLint Rules: Enable array-callback-return to catch missing returns in reduce/map at build time.
  • TypeScript: Static types immediately warn that total returns void instead of number.
  • Unit Testing: Always test edge cases (empty list [], single item, null items).
